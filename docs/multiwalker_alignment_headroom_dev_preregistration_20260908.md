# Multiwalker privileged Lyapunov-alignment headroom gate

## Single kill question

The already confirmed Multiwalker result establishes dynamic cached-profile
return value. This experiment asks the missing theorem-facing question:
under the same local policy-cache dynamics and prefix communication budget,
does a dynamic refresh schedule create material **one-update Lyapunov descent
potential** above a strong online scheduling envelope?

No online critic is fitted. Exact simulator branches and future values are
privileged development information. A failure stops the Multiwalker alignment
controller line; a pass permits only a separately frozen selected-feedback
critic development split.

## Frozen model and estimand

Five distinct tanh actors interact in PettingZoo Multiwalker. The training-time
cache graph is the five-node chain. At each launch, the owner uses its current
actor and recipient-specific cached versions of its graph neighbors. Actors
outside the declared local dependency set are current, so unreachable
long-range cache error is not silently assigned to a local edge decision.

Each five-launch epoch uses a new random permutation of all owners. Thus every
owner is updated four times in twenty launches, while launch order is not a
fixed cyclic artifact. The public state prefix is generated with all-current
actors and is identical across counterfactual cache actions.

At launch `p`, a centered action finite difference of the four-step discounted
return produces a deterministic policy-gradient loss packet `g_p(a)` for each
reachable cache state and null-or-one-edge action. The all-current profile
produces the privileged reference `g_p^ref`. The primary per-launch value is

\[
 D_p(a)=\max_{0\leq\alpha\leq1}
 \left\{\alpha\langle g_p^{\rm ref},g_p(a)\rangle
 -\frac12\alpha^2\lVert g_p(a)\rVert^2\right\}.
\]

This is exactly the scalar packet-weight minimization in the normalized
smoothness part of the core Lyapunov drift. It tests edge choice and packet
weight jointly. It is not yet a certificate for the true nonlinear objective:
the final theorem must replace the normalized constant by a proved or bounded
smoothness term and carry reference, finite-difference, Markov, and receipt
motion errors.

## Exact and online schedules

For each owner, dynamic programming enumerates every reachable neighbor-cache
state and binary refresh-cost sequence. A multiple-choice binary program then
selects one option per owner subject to every one of the twenty global prefix
constraints

\[
 \sum_{s\le t} c(a_s)\le \lfloor r(t+1)\rfloor,
 \qquad r\in\{0.25,0.5\}.
\]

The exact oracle is compared against the envelope of myopic alignment, action
gap, parameter gap, age, round robin, random, fixed-left, fixed-right, and no
refresh. Every comparator can choose its own optimal scalar packet weight from
the same formula. Hence a positive gap cannot be attributed merely to tuning
`alpha` for the oracle.

## Frozen population and gates

Development seeds are `96300--96303`; no confirmation seeds are assigned.
The grid has two actor-drift scales, two budget rates, twenty launches, and a
four-step branch horizon, for sixteen reported seed-cells. Drift `0.04` is the
predeclared active population. All settings and H1--H12 are fixed in
`multiwalker_alignment_headroom_dev_config_20260908.json`.

The scientific thresholds are deliberately material rather than merely
positive: on active cells the exact schedule must recover at least 10% of the
gain above no refresh, beat the strong envelope in at least 75% of cells, and
have median headroom at least 0.5% of the ideal all-current reference descent.
All validity, exactness, budget, replay, owner-coverage, transition-accounting,
reference-signal, and nonzero-weight gates are also mandatory.
